# 階層型連合学習(HFL) AP選択シミュレーション：データ取得状況・指標調査レポート

本ドキュメントは、現状のシステムにおいて「どのデータが取得され、どのデータが取得できていないか」を徹底調査し、整理したものです。

## 1. 現状の取得済みデータ一覧

### A. モデル学習指標 (Learning Metrics)
通信ラウンドごとのモデル性能。連合学習が正しく進んでいるかを評価します。
| 指標名 | 記録形式 | 保存先 | 備考 |
| :--- | :--- | :--- | :--- |
| **Training Loss** | PNG, Pickle | `./save/` | エポックごとの損失推移 |
| **Training Accuracy** | PNG, Pickle | `./save/` | 学習データに対する正解率 |
| **Test Accuracy** | 標準出力 | コンソール | 推論時の満足度ランク予測精度 |

### B. ネットワーク・満足度指標 (System Metrics)
AP選択アルゴリズム（ハンガリアン法またはHFL推論）の適用結果。
| 指標名 | 記録形式 | 出力方法 | 備考 |
| :--- | :--- | :--- | :--- |
| **端末満足度の調和平均** | グラフ (Matplotlib) | `plt.show()` | システム全体の効率性を示す |
| **割当前満足度(Pre-satis)** | グラフ・標準出力 | `graph.py` | 比較用の初期/ランダム状態 |
| **満足度の移動平均** | グラフ | `graph.py` | 試行を通じた安定性の評価 |
| **AP割り当て結果** | 標準出力 | コンソール | どの端末がどのAPに繋がったかのIDリスト |
| **実行時間 (Execution Time)** | 標準出力 | コンソール | リアルタイムAP選択の実現可能性評価 |

## 2. 徹底調査によるデータ取得のギャップ（不足項目）

現状、計算ロジックは存在するが「ファイル保存」や「統計処理」が不十分な項目です。

### ① 公平性・分布の指標 (Fairness & Distribution)
- **最小満足度 (Min Satisfaction)**: システム内で最も不利益を被っている端末の状態。平均値では隠れてしまう「格差」の評価に必須。
- **個別満足度の全データ**: 端末ごとの満足度分布（ヒストグラム等）。現在は平均値に集約されており、個別の推移が追えない。

### ② 制約・コストの指標 (Constraints & Costs)
- **容量超過端末数 (Capacity Overlap)**: 物理的な通信容量を超えて割り当てられた端末の数。`output.py` でコメントアウトされている。
- **AP切り替えコスト (Handover/Switching Cost)**: 前回のステップからAPが変更された回数。頻繁な切り替えは通信の不安定化を招くが、現在はカウントされていない。

### ③ インフラ負荷の推移 (Infrastructure Load)
- **APごとの接続台数推移**: `linkTerm` という変数には存在するが、永続的なログ（CSV等）として書き出されていない。

---

## 3. 実装上の技術的課題

- **出力の揮発性**: 満足度の詳細な計算過程や最終結果の多くが「標準出力（コンソール）」と「ポップアップグラフ」のみに依存しており、実行後にデータが消失しやすい。
- **コメントアウトされたロジック**: `HFL_main.py` および `output.py` において、CSV出力や容量計算のコードがコメントアウト状態にあり、本来持っている機能をフルに活用できていない。

---

## 4. 今後の改善提案

1.  **自動ファイル保存の強化**: `graph.py` に `plt.savefig()` を追加し、実行ごとに満足度の推移画像を自動保存する。
2.  **CSVロガーの有効化**: `output.satisLimit` を修正・再稼働させ、時系列の満足度データをCSV形式で蓄積する。
3.  **統計指標の追加**: 記録対象に「最小満足度」と「満足度の標準偏差」を追加し、公平性の観点から評価を補強する。
4.  **切り替えログの作成**: APが切り替わったタイミングと回数を記録し、制御の安定性を可視化する。
