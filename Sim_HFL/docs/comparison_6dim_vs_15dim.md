# 6次元 vs 15次元 AP選択モデル 比較レポート

**作成日**: 2026-05-13
**対象フレームワーク**: HFL_AP_selection-main, Sim_HFL

---

## 1. 背景と目的

### 1.1 動機・きっかけ

教師データはハンガリアン法によって「その瞬間のAP状態に基づく最適割り当て」を正解ラベルとして生成している。しかし実際のAPのTP/RTT/接続台数は秒単位で動的に変化するため、教師データ生成時点の最適解が推論実行時にはすでに最適でなくなっている。

この**静的な教師データと動的な現実のミスマッチ**が、モデルの精度はそれなりに高い（60-78%）にもかかわらず端末満足度が改善しない主因と推測された。6次元モデルは端末自身の要求（TP要件、RTT要件、アプリ種別）しか見ていないため、現在のAP状態の変動に対応できない。

そこで、AP状態（各APのTP、RTT、接続台数）を入力特徴量に追加することで、モデルが「現在のAP状態を考慮した上で」AP選択を判断できるようにし、動的変動への耐性を高めることを目指した。

### 1.2 検証目的

階層型連合学習 (HFL) による AP 選択において、入力特徴量にAP状態（TP, RTT, 接続台数）を追加することで割当品質が向上するかを検証する。

| モデル | 入力次元 | 特徴量構成 |
|--------|----------|-----------|
| Legacy (6次元) | 6 | `[tp_norm, rtt_norm, app_one_hot(4)]` |
| New (15次元) | 15 | `[tp_norm, rtt_norm, app_one_hot(4), AP0_tp, AP0_rtt, AP0_n, AP1_tp, AP1_rtt, AP1_n, AP2_tp, AP2_rtt, AP2_n]` |

## 2. 実験一覧

### Trial 1: 2AP / HFL_AP_selection-main / initRTT=[100, 130]

**条件**: 4端末, 2AP, 2エッジサーバ, erlang_n=[10, 5], hidden_size=8 (初期)

| 指標 | 6次元 | 12次元 (AP状態) |
|------|-------|----------------|
| Test Accuracy | 49.5% | **24%** (全端末AP1に固定) |

**問題**: hidden_size=4 (=output_size) がボトルネック。12次元入力を4ニューロンで圧縮しきれず、全端末がAP1（最悪AP）に割り当てられた。

**修正**: `hidden_size = max(termNum, input_size * 2)` に変更。

### Trial 2: 2AP / HFL_AP_selection-main / initRTT=[100, 130] (hidden_size修正後)

**条件**: 4端末, 2AP, 2エッジサーバ, erlang_n=[10, 5], hidden_size=max(4, input_size*2)

| 指標 | 6次元 | 12次元 |
|------|-------|--------|
| Test Accuracy | ~50% | ~50% |
| 最終満足度 | ほぼ同等 | +0.0083 (微差) |

**結果**: 精度も満足度も実質的に同一。差は誤差範囲内。

### Trial 3: 3AP / HFL_AP_selection-main / initRTT=[90, 100, 110]

**条件**: 4端末, 3AP, 2エッジサーバ, erlang_n=[10, 5, 3], RTT変動=15ms

| 指標 | 6次元 | 15次元 |
|------|-------|--------|
| Test Accuracy | ~同等 | ~同等 |
| AP2使用率 | 0% | 0% |
| 満足度差 | — | 実質同等 |

**結果**: AP2（RTT=110, n=3）は両モデルとも選択せず。問題が2AP相当に退化。

### Trial 4: 3AP / HFL_AP_selection-main / 改善適用 (pre-state + cross features)

**改善内容**:
1. 教師データのAP状態を「割当前」の値に修正（推論時の分布と一致）
2. クロス特徴量の追加: `tp_ratio = AP_tp / needTP`, `rtt_ratio = needRTT / AP_rtt`

| 指標 | 6次元 | 15次元 + cross |
|------|-------|---------------|
| Test Accuracy | ~同等 | ~同等 |
| 満足度 | — | 有意差なし |

**結果**: 改善を適用しても精度・満足度に有意差は生じなかった。

### Trial 5: 3AP / Sim_HFL / M/M/1+Erlang-B (本試行)

**条件**:
- 4端末, 3AP, 2エッジサーバ (edge-00: T0,T1 / edge-01: T2,T3)
- AP0: tp=250Mbps, RTT=90ms, mu=8, n_ch=2 (混雑しやすい)
- AP1: tp=200Mbps, RTT=100ms, mu=12, n_ch=5 (中間)
- AP2: tp=150Mbps, RTT=110ms, mu=15, n_ch=10 (安定)
- ネットワーク: M/M/1 + Erlang-B（実機 virtual_congestion.py と同一）
- HFL: 30グローバルラウンド x 5ローカルラウンド x 5エポック
- LR=0.0001, AdamW, LayerNorm, Dropout=0.1 (実機 LocalTrainer.kt 同一)
- 教師データ: 3000サンプル, ハンガリアン法で最適割当生成

### 3.3 AP分布の推移

**6次元モデル** — 不安定な振動パターン:
```
R 1: [2,2,0] → R 2: [4,0,0] → R 3: [2,0,2] → R 4: [2,2,0] (安定期)
...
R14: [2,2,0] → R15: [4,0,0] → R16: [4,0,0] → R17: [2,2,0]  (振動再開)
...
R25: [4,0,0] → R26: [4,0,0] → R27: [4,0,0] → R28: [2,2,0]  (振動継続)
```
全4台がAP0に集中するラウンドが頻発 → 混雑で満足度が0.14台に急落。

**15次元モデル** — 安定した分布:
```
R 1: [2,2,0] → R 2: [4,0,0] → R 3: [2,2,0] (以降R30まで [2,2,0] で固定)
```
R3以降28ラウンド連続で切替なし。AP状態を認識し「AP0に全員集中すると混雑する」ことを学習。

## 4. 全試行の横断的考察

### 4.1 精度 (val_acc) は一貫して差がない

全5試行を通じ、6次元と15次元の分類精度に統計的有意差は一切観察されなかった。

| 試行 | AP数 | フレームワーク | 6次元 acc | 15次元 acc | 差 |
|------|------|---------------|-----------|------------|-----|
| Trial 1 | 2 | HFL_AP_selection | 49.5% | 24% (bug) | — |
| Trial 2 | 2 | HFL_AP_selection | ~50% | ~50% | ~0 |
| Trial 3 | 3 | HFL_AP_selection | ~60% | ~60% | ~0 |
| Trial 4 | 3 | HFL_AP_selection | ~60% | ~60% | ~0 |
| Trial 5 | 3 | Sim_HFL | 62.3% | 60.0% | -2.3pt |

**理由**: AP選択の最適解は主にアプリ要件（needTP, needRTT）で決まる。AP状態は「どのAPが混んでいるか」の情報だが、教師データではハンガリアン法が全端末の情報をグローバルに最適化しているのに対し、推論は端末単体で独立に行われる。この構造的なミスマッチにより、AP状態特徴量は「分類精度」の向上には寄与しない。

### 4.2 満足度は15次元が安定的に優位 (Trial 5で顕著)

Trial 5 において、15次元モデルは満足度の全指標で6次元を上回った:
- HM satisfaction: +17.6% 改善 (0.2219 → 0.2609)
- avg satisfaction: +20.3% 改善 (0.2839 → 0.3416)
- 最低値の底上げ: min HM が 0.1432 → 0.2006 (+40.1%)

この差は精度からは予測できない。精度は同等なのに満足度が異なるのは、**AP状態の認識が「不必要な切替の抑制」に作用している**ためである。

### 4.3 メカニズム: AP状態による切替抑制

15次元モデルの優位性の本質は「AP状態を見て混雑APへの移動を避ける」ことにある。

```
6次元の行動パターン:
  アプリ要件だけ見る → AP0が最適と判断 → 全員AP0へ → 混雑 → 満足度急落
  → 次ラウンドで一部戻る → また全員AP0へ → 振動

15次元の行動パターン:
  アプリ要件 + AP状態を見る → AP0は混雑と認識 → 不要な切替を抑制 → 安定
```

具体的に、6次元モデルは30ラウンド中12ラウンドで切替が発生し（計24回の端末切替）、15次元モデルは2ラウンドのみ（計4回）。切替が少ないこと自体が良いわけではなく、**混雑するAPへの集中を避けた結果として切替が不要になった**点が重要である。

### 4.4 両モデル共通の限界

1. **AP2は未使用**: RTT=110ms（最悪）のAP2は全試行で一度も選択されなかった。3APだが実質2APの問題に退化。

2. **満足度自体が低い (0.2〜0.3)**: AP0 (mu=8, n_ch=2) は2台でも M/M/1 が飽和に近く RTT が急騰する設定。根本的にネットワークキャパシティが不足。

3. **独立予測 vs グローバル最適化のギャップ**: 推論時は各端末が独立に予測するため、「他の端末がどう動くか」を考慮できない。ハンガリアン法（教師）はグローバル最適化だが、モデルはローカル決定しかできない。

---

## 5. 結論

### 精度について
6次元と15次元の分類精度に有意差はない。AP状態特徴量はハンガリアン法の最適解を近似する上で冗長であり、精度向上には寄与しない。

### 満足度について
15次元モデルは6次元モデルより満足度が安定的に高い (HM +17.6%, avg +20.3%)。これは精度の差ではなく、AP状態認識による**切替抑制効果**に起因する。AP0への全端末集中（混雑→満足度急落）を防ぎ、分散を維持する行動を学習している。

### 実用上の意味
- 精度向上を目的とするなら、次元数の追加は不要
- 実運用での安定性（不要なAP切替の削減、混雑回避）を重視するなら、15次元モデルに利点がある
- ただし、独立端末予測の構造的限界は次元数では解決できない

### 今後の検討事項
1. **AP数・端末数の増加**: 4端末3APは小規模すぎ、統計的な差が出にくい
2. **動的負荷変動**: 現在は各ラウンドで独立にAP条件を生成しているが、時系列的な負荷変動（特定時間帯に特定APが混む等）があればAP状態の価値が高まる可能性
3. **マルチエージェント協調**: 端末間で推論結果を共有し、集中を事前に回避する仕組み
