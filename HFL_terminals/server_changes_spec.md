# サーバ側変更仕様書

## 概要
本仕様書は、クライアントアプリケーションの変更に伴い、サーバ側で必要な変更点を記載したものです。これにより、クライアントとサーバ間の通信が正しく行われるようにします。

## 変更点

### 1. 端末IDの管理
- **目的**: クライアントがサーバから一意の端末IDを取得し、ローカルに保存する仕組みを導入。
- **変更内容**:
  - 新しいエンドポイント `/api/v1/get_terminal_id` を追加。
  - **リクエスト**: クライアントからのリクエストには以下の情報を含む。
    - デバイス情報（例: OSバージョン、アプリバージョンなど）
  - **レスポンス**: サーバは以下の情報を返す。
    - `terminal_id` (string): 一意の端末ID。

### 2. ラウンド状態の管理
- **目的**: クライアントがサーバから最新のラウンド情報を取得し、学習プロセスを同期。
- **変更内容**:
  - 既存の `/api/v1/meta` エンドポイントを拡張。
  - **レスポンス追加項目**:
    - `round` (int): 現在のラウンド番号。
    - `model_id` (string): 現在のモデルの識別子。

### 3. 学習結果のアップロード
- **目的**: クライアントが学習結果をサーバに送信し、サーバがそれを処理。
- **変更内容**:
  - 新しいエンドポイント `/api/v1/upload_training_result` を追加。
  - **リクエスト**: クライアントから以下の情報を受け取る。
    - `terminal_id` (string): クライアントの端末ID。
    - `round` (int): 学習が行われたラウンド番号。
    - `accuracy` (float): 学習の精度。
    - `loss` (float): 学習の損失値。
    - `timestamp` (int): 学習結果のタイムスタンプ。
  - **レスポンス**: サーバは以下の情報を返す。
    - `status` (string): 処理結果（例: `success` または `error`）。

### 4. モデル更新の通知
- **目的**: サーバがクライアントに新しいモデルが利用可能であることを通知。
- **変更内容**:
  - 既存の `/api/v1/meta` エンドポイントを拡張。
  - **レスポンス追加項目**:
    - `new_model_available` (boolean): 新しいモデルが利用可能かどうか。

## 注意事項
- クライアントとサーバ間の通信はすべて HTTPS を使用してください。
- エンドポイントの認証にはトークンベースの認証を使用してください。
- サーバ側の変更は後方互換性を保つように実装してください。
