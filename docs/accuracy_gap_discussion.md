## 2. 4/29→5/7 での精度改善（+8.4%）

### 学習パイプラインの改善経緯

4/29→5/7の間にローカル学習パイプライン全体を見直し、以下の改善を実施：

1. **学習・推論モード遷移の正規化**
   - バリデーション実行後にモデルが推論モードのまま次エポックに進む問題を修正
   - 推論モード時は中間計算結果がキャッシュされない設計のため、後続エポックの勾配計算が不正確になっていた
   - 各エポック終了時のモード遷移を明示的に管理するよう修正

2. **メモリ最適化の導入**
   - 逆伝播完了後の中間キャッシュ解放機構を追加
   - 推論モードでのキャッシュ保存スキップによるGC負荷軽減

3. **その他のパイプライン安定化**
   - NetworkClient、TrainingViewModel、UploadMetricsWorker等の通信周りの改善

### 改善の効果

- 改善前（4/29）: エポック1のみ正確な勾配計算、エポック2以降は不正確な中間値に基づく勾配更新
- 改善後（5/7）: 全5エポックで正確な勾配計算
- **学習が正常に全エポック機能するようになったことが精度向上の主因**

## 3. 実機 vs シミュレーション 1.4%差の妥当性検証

### 差が小さい構造的理由

現在の実験設定は**シミュレーションと実機で差が出にくい条件**が揃っている：

| 要因 | 現在の設定 | 差が出る設定 |
|------|-----------|-------------|
| データ分布 | IID（均等分割） | Non-IID（Dirichlet α=0.1） |
| 教師データ | 全端末で同一CSV | 端末ごとに異なるデータ源 |
| モデル規模 | 極小MLP（6→32→4） | 大規模モデル（収束に時間要） |
| 端末数 | 4台 | 10-50台（straggler影響大） |
| 通信影響 | 学習後のアップロードのみ | 学習中の通信依存あり |
| ラウンド数 | 5（十分に収束） | 多数（途中脱落が精度に影響） |

### 通信遅延が精度に直接影響しない理由

```
[現在のHFL学習フロー]
端末がグローバルモデル受信 → ローカルで5epoch学習（通信なし）→ 重み送信 → エッジ集約 → セントラル集約

ローカル学習は端末内で完結するため、通信遅延100msは学習精度自体に影響しない。
影響するのは「ラウンドに間に合うか」（端末脱落）のみ。
現在の設定では100msで脱落は発生しない。
```

### 80%付近での収束（天井効果）

- 教師データのラベル分布: AP_0=69%, AP_1=31%（不均衡）
- モデル容量: 6→32→4 の小規模MLP
- 実機もシミュレーションも**同じ天井（≈80%）に到達**している可能性
- 精度の天井はタスク難易度・データ品質・モデル容量で決まり、実行環境には依存しない

### 1.4%差の内訳（推定）

| 要因 | 寄与 |
|------|------|
| 浮動小数点精度差（Kotlin Float vs Python Float32） | ~0.5% |
| バッチ順序・乱数シードの差 | ~0.5% |
| 集約時の端末重み付けの微差 | ~0.4% |
| 通信遅延による影響 | ≈0%（上記の通り） |

### 妥当性の結論

**1.4%差は「シミュレーションが優れている」のではなく、「差が出にくい実験条件」の結果。**

正当化できるポイント：
- 同一教師データ・同一モデル構造・IID分割では、実行環境の差は精度にほぼ反映されない
- ローカル学習が端末内完結するFLアーキテクチャでは、通信品質は精度ではなく「完走率」に影響
- 小規模MLPは少ないエポックで収束するため、端末間の処理速度差が蓄積しない

**ただし、この結果をもって「スケールアップしても差が出ない」とは言えない。**

## 4. 差を出すための今後のシナリオ

シミュレーションと実機の乖離を測定し、シミュレータの限界を明らかにするには：

| シナリオ | 期待される効果 |
|----------|----------------|
| Non-IID分割（Dirichlet α=0.1-0.5） | 端末間のデータ偏りで集約品質に差が出る |
| 端末数増加（8-16台） | straggler・部分参加の影響が顕在化 |
| 通信タイムアウトの導入（厳しめ設定） | 端末脱落率の違いが精度に反映 |
| ラウンド数増加（10-30） | 長期学習での累積誤差の検証 |
| 教師データの動的生成 | 端末固有のデータ特性の反映 |

## 5. メモリ最適化の効果

精度に対してはメモリON/OFFで差なし（78.1% vs 78.1%）。
メモリ最適化の価値は**精度以外**にある：

| 指標 | メモリON | メモリOFF |
|------|---------|----------|
| 精度 | 78.1% | 78.1% |
| メモリ使用量 | 削減 | 高い |
| OOMリスク | 低 | 高（長時間運用で蓄積） |
| アップロード成功率 | 高 | 端末脱落リスクあり |
