# サーバ側変更仕様書

## 概要
本仕様書は、クライアントアプリケーションの変更に伴い、サーバ側で必要な変更点を記載したものです。これにより、クライアントとサーバ間の通信が正しく行われるようにします。

## 変更点

### 1. 端末IDの管理
- クライアントがサーバから一意の端末IDを取得し、ローカルに保存する仕組みを導入。
- 新しいエンドポイント `/api/v1/get_terminal_id` を追加。
  - リクエスト: デバイス情報（OSバージョン、アプリバージョン等）
  - レスポンス: `terminal_id` (string)

### 2. ラウンド状態の管理
- クライアントがサーバから最新のラウンド情報を取得し、学習プロセスを同期。
- 既存の `/api/v1/meta` エンドポイントを拡張。
  - レスポンス追加項目: `round` (int), `model_id` (string)

### 3. 学習結果のアップロード
- クライアントが学習結果をサーバに送信し、サーバがそれを処理。
- 新しいエンドポイント `/api/v1/upload_training_result` を追加。
  - リクエスト: `terminal_id`, `round`, `accuracy`, `loss`, `timestamp`
  - レスポンス: `status` (string)

### 4. モデル更新の通知
- サーバがクライアントに新しいモデルが利用可能であることを通知。
- 既存の `/api/v1/meta` エンドポイントを拡張。
  - レスポンス追加項目: `new_model_available` (boolean)

## 注意事項
- 通信はすべて HTTPS を使用。
- エンドポイントの認証はトークンベース認証。
- サーバ側の変更は後方互換性を保つこと。
