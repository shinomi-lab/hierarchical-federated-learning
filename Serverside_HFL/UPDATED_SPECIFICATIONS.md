# 更新された仕様書

## 概要
このドキュメントでは、中央サーバーおよび端末サーバーにおける最新の変更点について説明します。これらの変更は、ログ管理とラウンド状態管理の一貫性を向上させ、サーバーのシャットダウンおよび再起動時の動作を最適化することを目的としています。

---

## 変更点

### 1. ログ管理の統一
- **目的**: ログファイルの作成場所とフォーマットを統一。
- **変更内容**:
  - ログ設定を`logging_config.py`に集約。
  - `central_server`と`edge_server`の両方で共通の設定を使用。
  - ログファイルは`logs/time_records/`ディレクトリに作成され、ファイル名は`<server_name>_YYYYMMDD_HHMMSS.log`形式。
- **影響範囲**:
  - `central_server/main.py`
  - `edge_server/main.py`
  - `edge_server/logging_config.py`

### 2. ラウンド状態管理の永続化
- **目的**: サーバーのシャットダウン後もラウンド状態を保持し、再起動時に復元可能にする。
- **変更内容**:
  - `RoundState`クラスに状態の保存・読み込み機能を追加。
  - シャットダウン時に状態をJSONファイルに保存。
  - 再起動時に保存された状態を読み込み。
- **影響範囲**:
  - `central_server/state.py`
  - `central_server/main.py`

### 3. サーバーライフサイクルイベントの処理
- **目的**: サーバーの起動およびシャットダウン時の動作を明確化。
- **変更内容**:
  - 起動時:
    - 新しいログファイルを作成。
    - 保存されたラウンド状態を読み込み。
  - シャットダウン時:
    - 現在のラウンド状態を保存。
    - ログファイルに終了メッセージを記録。
- **影響範囲**:
  - `central_server/main.py`

---

## 使用方法

### 1. サーバーの起動
- **コマンド**:
  ```bash
  python central_server/main.py
  ```
- **動作**:
  - 新しいログファイルが作成されます。
  - 保存されたラウンド状態が復元されます。

### 2. サーバーのシャットダウン
- **方法**:
  - サーバーを手動で停止します（例: Ctrl+C）。
- **動作**:
  - 現在のラウンド状態が`round_state.json`に保存されます。
  - ログファイルに終了メッセージが記録されます。

## ディレクトリ構造
```
logs/
  time_records/
    central_server_<timestamp>.log
    edge_server_<timestamp>.log
round_state.json
```

---

## 注意点
- ログファイルはサーバーごとに作成され、タイムスタンプで区別されます。
- `round_state.json`は中央サーバーの状態を保持するために使用されます。削除しないでください。
