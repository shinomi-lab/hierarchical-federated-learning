# 実験規模の暫定構成（台数・Docker）

> **ステータス**: 暫定（議論ベースの目安。研究費・機材確保後に確定すること）  
> **更新想定**: 実機台数・Docker 方針が固まり次第

---

## 背景（この文書の前提）

- 卒業研究で **実機 Android 3 台・エッジ 2・セントラル 1・AP 2** の実験は完了済み。
- 修士論文では **シミュレーション済みの結果と、実装・現実ノイズを含む実機での効果**を比較するのが主線。
- **主張の核は実機＋生データ**。Docker 仮想端末は **Android の代替にはならず**、使う場合は **サーバ再現・負荷・補助実験**に限定するのが無難。
- 普段のサーバ起動は **ターミナル（venv + uvicorn）** でよい。**提出・再現性**のために **Docker（サーバ群）** を用意する、という整理と整合する。

---

## 共通の固定トポロジ

| 要素 | 内容 |
|------|------|
| エッジサーバー | **2 台** |
| セントラルサーバー | **1 台** |
| AP（ルータ） | **2 台** |
| 端末割当の例 | エッジ 0 に多め・エッジ 1 に少なめ（例: **2 + 1**） |

---

## 1. Docker **なし**版

### 1.1 理想的な台数構成

| 区分 | 台数・内容 |
|------|------------|
| **Android 実機 合計** | **8〜10 台** |
| 内訳の目安 | **スマホ 5〜6** ＋ **タブレット 3〜4** |
| OS の目安 | **API 33〜34（Android 13〜14）** を優先（通知権限・コード分岐との整合） |
| メーカー | **2 ブランド以上**（表で明示できると一般化の説明がしやすい） |
| 学習データ | **FedAvg に参加させる学習は実機の生データのみ**（主結果の芯） |
| サーバ | **ターミナル直起動**で可 |

### 1.2 最低要件の台数構成

| 区分 | 台数・内容 |
|------|------------|
| **Android 実機 合計** | **5〜6 台** |
| 目安 | **既存スマホ 3** ＋ **タブレット 2**（余裕があれば **+1 台**） |
| 意味 | 卒論の 3 台より明確に増えた **修士としての下限ライン寄り** |
| **絶対下限** | **3 台** — プロトコルは回るが、「卒論からの伸び」としては弱い（予算制約時は **限界と明記**） |

---

## 2. Docker **あり**版

Docker は **(A) サーバの再現環境** と **(B) 仮想クライアント** に分けて考える。

### 2.1 理想的な台数構成

| 区分 | 台数・内容 |
|------|------------|
| **Android 実機** | **8〜10 台**（Docker なし版の理想と同じ） |
| **Docker（サーバ）** | **セントラル 1 ＋ エッジ 2 ＋ Redis 1**（再現性・査読用） |
| **Docker（仮想端末）** | **同時 8〜12、上限 15** を **補助**と定義 |
| 仮想の位置づけ（推奨） | **主実験の FedAvg には混ぜない**。集約待ち・HTTP 負荷・プロトコル挙動の評価用。混ぜる場合は **別条件・別表・感度分析**として明示。 |
| 普段運用 | サーバは **ターミナル**でも可。**提出・スナップショット**で Docker を回す運用と両立可 |

### 2.2 最低要件の台数構成

| 区分 | 台数・内容 |
|------|------------|
| **Android 実機** | **5 台**（スマホ 3 ＋ タブレット 2） |
| **Docker** | **サーバスタックのみ**（中央・エッジ・Redis）。**仮想端末 0 でも可** |
| **仮想を足す場合** | **4〜6 台**に抑え、**主集約は実機のみ**、仮想は **負荷・動作確認**に限定 |

## 3. 対照一覧（暫定）

| | **理想（Docker なし）** | **最低（Docker なし）** | **理想（Docker あり）** | **最低（Docker あり）** |
|--|-------------------------|-------------------------|---------------------------|----------------------------|
| **実機 Android** | **8〜10** | **5〜6**（限界 **3**） | **8〜10** | **5** |
| **サーバ** | ターミナル | ターミナル | **＋ Docker 再現** | **＋ Docker 再現** |
| **仮想クライアント** | なし | なし | **8〜12（補助）** | **0〜6（任意）** |
| **主 FedAvg（推奨）** | 実機のみ | 実機のみ | 実機のみ | 実機のみ |

---

## 4. 論文・計画書向けの短文（案）

**理想（暫定）**: 実機 **8〜10 台** で端末多様性と参加者数を確保し、シミュレーション結果と対比する。サーバ環境の再現には Docker を用い、仮想クライアントはプロトコル・負荷評価の補助に限定し、主たる連合学習の更新は実機の生データのみを用いる。

**最低（暫定）**: 実機 **5 台**（スマホ 3 ＋ タブレット 2）を下限とし、Docker はサーバ再現に限定する。仮想端末は必須としない。
